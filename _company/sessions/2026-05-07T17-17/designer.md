## 📱 앱 UI/UX 디자인 가이드라인 및 개발 로드맵 제시

CEO님의 지시에 따라, 기존에 확정된 브랜드 컬러 시스템과 핵심 컴포넌트를 모바일 애플리케이션(App) 환경에 최적화된 디자인 가이드라인으로 변환하고, 확보된 상품 데이터 분석을 기반으로 초기 개발 로드맵을 즉시 시작합니다.

### 1. 앱 비주얼 시스템 (Visual System) 설계

기존의 브랜드 정체성(`Abibi Blue`, `Reward Gold`, `Cat Warmth`)과 핵심 컴포넌트를 모바일 환경에 맞게 재해석하여 UI/UX 디자인 가이드라인을 제시합니다.

#### 1.1. 컬러 팔레트 적용 (Color Application)

| 명칭 | HEX 코드 | 용도 및 설명 (앱 내 역할) | 브랜드 연관성 |
| :--- | :--- | :--- | :--- |
| **Abibi Blue** | `#4A90E2` | **Primary Color:** 핵심 CTA 버튼, 주요 탐색 바(Navigation Bar), 시스템 알림 등 기능적 요소에 사용. 신뢰감과 안정감을 부여하며, 앱의 기본 톤을 설정함. | 브랜드 아이덴티티 |
| **Reward Gold** | `#FFD700` | **Accent Color:** 보상 포인트, 긍정적 피드백, 레벨 달성 표시 등 사용자에게 기쁨과 동기부여를 주는 요소에 사용. 희소성과 가치를 강조함. | 보상 및 프리미엄 감성 |
| **Cat Warmth** | `#F5E6D0` | **Background/Surface Color:** 메인 배경, 카드(Card) 영역, 입력 필드 등 사용자에게 편안하고 따뜻한 경험을 제공하는 주요 인터페이스 영역에 사용. 친근함과 안정감을 극대화함. | 감성 및 웰니스 |
| **Neutral Gray** | `#E0E0E0` | **Secondary Color:** 구분선, 비활성 텍스트, 배경 분리 등에 사용하여 정보의 위계를 명확히 하고 가독성을 높임. | 구조 및 명료성 |

#### 1.2. 타이포그래피 시스템 (Typography System)

*   **폰트:** 시스템 환경에 따라 `Noto Sans KR` 또는 `Pretendard` 사용을 권장합니다. (친근함과 데이터 기반의 직설적인 톤 유지)
*   **Hierarchy:** 정보의 중요도에 따라 명확하게 구분합니다.
    *   **H1 (앱 제목):** Bold, Large Size (예: 28pt) - 앱의 핵심 기능 강조
    *   **Body Text:** Regular, Readable (예: 16pt) - 상세 설명 및 데이터 표시
    *   **Label/Caption:** Medium, Light Weight (예: 12pt) - 보조 정보 및 설정 항목

#### 1.3. 핵심 컴포넌트 정의 (Core Components)

| 컴포넌트 | 디자인 지침 | 컬러 적용 예시 | UX 목표 |
| :--- | :--- | :--- | :--- |
| **Primary Button** | `Abibi Blue` 배경, 흰색 텍스트. 충분한 패딩(Padding) 확보. | 배경: `#4A90E2`, 텍스트: `#FFFFFF` | 명확한 행동 유도 (CTA), 사용자의 즉각적인 반응 유도 |
| **Reward Badge** | `Reward Gold` 색상으로 채워진 원형 또는 배지 형태. | 배경: `#FFD700`, 테두리: `Abibi Blue` | 성취감 부여, 보상의 가치 시각화 |
| **Content Card** | `Cat Warmth` 배경에 미세한 그림자(Shadow) 적용하여 입체감을 부여. | 배경: `#F5E6D0`, Shadow: Light Gray | 정보의 그룹화 및 편안한 읽기 경험 제공 |
| **Input Field** | 테두리(`Neutral Gray`)를 사용하여 입력 영역을 명확히 구분. 포커스 시 `Abibi Blue`로 변경. | Border: `#E0E0E0`, Focus: `#4A90E2` | 데이터 입력의 정확성 및 직관성 확보 |

### 2. 앱 개발 초기 기획 (App Development Roadmap & Planning)

확보된 상품 데이터 분석 결과와 디자인 가이드라인을 바탕으로, **MVP(Minimum Viable Product)** 달성을 목표로 하는 단계별 로드맵을 제시합니다.

#### Phase 1: Discovery & Foundation (기반 다지기) - 기간: 2주

**목표:** 핵심 기능 정의 및 기술 스택 확정.
*   **데이터 통합:** Business 에이전트 분석 결과(원가 대비 프리미엄 전략, 포트폴리오 배분)를 앱의 **수익화 모델 설계**에 직접 반영합니다. (구독/보상 시스템의 가격 책정 기준 설정)
*   **UX Flow 확정:** '고양이 기분 측정 및 보상' UX 흐름을 모바일 환경에 맞게 최종 와이어프레임(High-fidelity)으로 재구성합니다.
    *   *핵심 플로우:* 로그인 → 오늘의 기분 측정 (감성 입력) → 리포트 확인 → 보상 시스템 접근 → 보상 사용.
*   **기술 스택 결정:** React Native 또는 Flutter 중 빠른 MVP 구현에 유리한 프레임워크를 최종 선정합니다.

#### Phase 2: Wireframing & Design System Implementation (뼈대 및 디자인 적용) - 기간: 3주

**목표:** 기능적 구조 확립 및 시각 시스템 적용.
*   **Low-Fidelity 와이어프레임 제작:** Phase 1에서 정의된 플로우를 기반으로 모든 핵심 화면의 레이아웃을 설계합니다. (Designer 메모리 기반)
*   **High-Fidelity UI 디자인:** 섹션 1에서 확정된 **컬러 팔레트, 타이포그래피, 컴포넌트 가이드라인**을 적용하여 모든 화면의 최종 디자인(Mockup)을 제작합니다. (앱 내 'Warm Dashboard' 스타일 적용)
*   **Design System 구축:** 재사용 가능한 컴포넌트 라이브러리(버튼, 카드, 네비게이션 등)를 정의하고 Figma에 구현하여 일관성을 확보합니다.

#### Phase 3: MVP Development & Testing (MVP 개발 및 검증) - 기간: 6주

**목표:** 핵심 기능 중심의 최소 실행 가능한 제품 출시.
*   **백엔드 구축:** 데이터베이스(상품, 사용자 기분 기록, 보상 내역)를 포함한 API 서버를 구축합니다.
*   **프론트엔드 개발:** Phase 2에서 설계된 디자인 시스템을 기반으로 핵심 기능(기분 입력, 포인트 지급/차감, 리포트 보기)을 구현합니다.
*   **알파 테스트:** 내부 사용자 그룹을 대상으로 핵심 플로우의 안정성과 UX 흐름을 검증합니다.
